# 위임 프롬프트 템플릿

모든 위임은 네 요소(의도 / 제약 / 완료 기준 / 관련 파일)로 쓴다(핸드북 §9.3). 「다시 확인하라」류의 검증 지시는 넣지 않는다 — 완료 기준 목록은 지시가 아니다. 범위 울타리 한 문장을 끝에 둔다.

## RED → multisession-tdd:test-writer

```
의도: 이슈 <N>(<제목>)의 계획 <경로> 절차 <번호들>의 테스트 줄을 실패하는 테스트로 옮긴다. 이 테스트는 GATE-1 뒤 동결되는 스펙이다.
제약: 테스트 줄 원문 — (전부 붙여 넣는다) / 수용 기준 원문 — (이슈·스펙에서 인용) / 프로덕션 코드는 컴파일용 스텁만 / 커밋·의존성 추가 금지 / 테스트 이름은 계획 줄 ID로 시작(`T01: …`).
완료 기준: 계획 줄마다 테스트 1개 · 실행해서 전부 실패(단언·동작 불일치) · 출력 ①~⑤.
관련 파일: (Explore 요약 100줄 이내 — 기존 테스트·픽스처·목 위치, 대상 프로덕션 파일)
요청받은 범위만 전달한다. 해석이 갈려 결과가 크게 달라질 때만 출력 ⑤로 묻는다.
```

## GREEN → multisession-tdd:implementer

```
의도: 이슈 <N> 절차 <번호>의 동결 테스트를 통과시키는 최소 구현.
제약:
- 통과시킬 테스트: (파일 · 이름 목록)
- RED sha <sha>. 테스트 경로(`config.sh get testGlobs` 목록)는 수정 금지 — 훅이 막는다. 틀렸다고 판단되면 RED-REOPEN 블록.
- 규약은 저장소 CLAUDE.md. 가정은 `[가정 N]` 주석. 계획 밖 파일 금지. 커밋 금지.
(재작업이면) 검토 피드백 — (판정의 번호와 문장 그대로)
완료 기준: 대상 테스트 통과 · 기존 테스트 통과 · 설정 checks 전부 통과 — (명령 목록) · 출력 ①~⑤.
관련 파일: (계획의 파일 목록 + Explore 요약)
요청받은 범위만 전달한다. 스코프를 조용히 넓히거나 좁히지 않는다.
```

## REFACTOR → multisession-tdd:refactorer

```
의도: 이슈 <N> GREEN 결과의 동작 보존 리팩토링. 할 것이 없으면 no-op.
제약: 테스트 경로 — (`config.sh get testGlobs` 목록) 수정 금지 / 한 패턴씩 · 매 단계 checks 전부 — (명령 목록) / 크기 여유 — 지금 파일 <n>개, 최대 <m>줄(참고 수치 <F>·<L>) / 커밋 금지.
완료 기준: checks 통과 · testdiff UNCHANGED(`sh <testdiff.sh 절대 경로>`) · 출력 ①~④.
관련 파일: (GREEN 변경 파일 목록)
```

## REVIEW → multisession-tdd:pr-reviewer

```
의도: 이슈 <N> 브랜치 <branch>의 PR 사전 리뷰. 결과는 GATE-3 패킷에 R-번호로 실린다.
제약: 읽기 전용 / 범위 `git diff <base>...HEAD`(base는 session.json의 base — 스택 PR이면 선행 브랜치) / 계획 <경로> / 수용 기준 매핑표 — (표) / 계획이 범위 밖으로 둔 것 — (목록)을 요구하지 않는다.
완료 기준: ① 차단 ② 강력 권고 ③ 제안 ④ 칭찬, 각 `R-# · 파일:줄 · 이유 · 제안`.
관련 파일: (numstat 목록)
```

`<… 절대 경로>`는 마스터가 SKILL.md에서 본 실제 경로로 바꿔 넣는다. 서브에이전트의 Bash 환경에는 플러그인 변수가 없다.
