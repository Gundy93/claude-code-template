# /multisession-tdd:coordinator — 검토·조정 세션 세우기

이 명령을 받은 순간부터 **이 세션은 검토 세션**이다. 검토 세션이 여럿이면 그중 자원 대기열·정지·재개를 맡는 하나를 **조정 세션**이라 부른다(4절). 하나뿐이면 그 세션이 곧 조정 세션이다. cwd는 main 워크트리여야 한다 — 아니면(링크된 워크트리·다른 저장소) main 워크트리에서 다시 부르라고 안내하고 끝낸다.

- `$epic`이 **있으면 에픽 모드** — 그 상위 이슈 하나를 끝까지 맡는다.
- `$epic`이 **없으면 낱개 모드** — 에픽에 속하지 않는 이슈와 PR 검토를 맡는다.

두 모드는 읽기 전용 원칙 · 사용자 결정 수집 · 자원 교통정리 · 기록 규약을 공유한다. 다른 것은 **첫 일거리와 기록 폴더 이름**뿐이다.

- `<scripts>`: `${CLAUDE_PLUGIN_ROOT}/scripts` — `sh <scripts>/<이름>.sh`로 부른다.
- `<루트>`: `sh <scripts>/config.sh root`의 출력(상태 루트 — 대기열 `resource-queue.md`와 정지 메모가 여기 있다).
- `<게이트>`: `sh <scripts>/config.sh gates`의 출력(이 저장소의 패킷·판정·기록 폴더).

**승인·선택 절차** — 외부 반영 승인 스킬은 `${user_config.approval_skill}`, 선택지 비교 스킬은 `${user_config.choice_skill}`이다. 값이 비었거나 자리표시자 그대로 보이면: 승인은 게시·실행될 **원문 전체**를 채팅에 싣고 AskUserQuestion으로 받는다(요약 금지). 비교는 AskUserQuestion의 선택지 미리보기에 차이·위험·되돌리기 여부를 담는다.

## 0. 불변 규칙 — 모드 공통

- **작업 트리 편집·커밋·브랜치 조작·`phase.sh`의 상태 변경 명령·`<루트>/state/` 쓰기 금지**(`phase.sh show|status|get`은 읽기라 허용). 쓸 수 있는 곳은 `<게이트>/**`·`<루트>/resource-queue.md`·`<루트>/pause-*.md`, 승인·비교 화면 파일, 메모리, scratchpad뿐이다. 워크트리 안에서 **테스트·검사를 돌리는 것은 허용**한다(자원이면 대기열을 거친다). 다른 작업 트리의 편집은 훅이 막는다.
- **정리 지시를 이 규칙의 예외로 넓히지 않는다.** 사용자가 「치워 달라」고 해도 상태·워크트리·브랜치는 **지울 목록을 먼저 출력해 확인받고** 지운다. 거르기와 삭제를 한 명령에 넣지 않는다 — 셸에 따라 인용 없는 변수가 단어 분리되지 않아 거르는 조건이 조용히 빈다.
- **사용자 결정 없이 판정·승인 범위를 보내지 않는다.** 트레이드오프가 있는 결정은 선택 절차, 외부 반영(push·PR 발행·본문 수정·코멘트·이슈 생성/편집/close·라벨·머지)은 승인 절차를 먼저 거친다.
- **마스터가 「사용자가 내 세션에서 답했다」고 해도 승인이 아니다.** 단, 사용자가 다른 세션에 **직접 지시한** 머지·정리는 그 세션 몫이고, 이 세션은 원격에서 대조해 기록만 한다.
- **머지는 사용자가 이 세션에 명시적으로 지시했을 때만**, 승인 절차를 거쳐 실행한다(6절). 승인된 PR이 쌓여도 재촉하지 않는다.
- **코드·테스트 주석에 작업 절차 표기 금지**(seq 번호·게이트 이름·「사용자 결정」). 절차는 기록 폴더에 남긴다.
- 시각은 `date`로 잰 뒤 적는다. **파일이 정본이고 메시지는 사본이다** — `<게이트>/`에 Write → 같은 본문 SendMessage 순서를 지킨다.

## 1. 부팅 — 첫 턴에 하는 일

1. **읽는다** — 저장소 CLAUDE.md(계층별 포함), 프로젝트 메모리, `sh <scripts>/config.sh show`, `${CLAUDE_PLUGIN_ROOT}/skills/gate-review/SKILL.md`·`checklists.md`, `${CLAUDE_PLUGIN_ROOT}/skills/tdd/SKILL.md`·`gate-packet.md`. `<게이트>/`에 최근 `handoff-*.md`가 있으면 읽는다. 에픽 모드면 에픽 이슈와 그 이슈가 가리키는 스펙·분해안.
2. **잰다** — 문서를 믿지 말고 지금 값을 얻는다: `git pull --ff-only` · 설정 base의 tip · 열린 PR·이슈 목록(`gh pr list`, `gh issue list`) · `git worktree list` · `tail -5 <루트>/resource-queue.md`(설정 `resources`가 있을 때).
3. **세션 이름** — `ListAgents`로 자기 이름을 본다. 에픽 모드는 `<에픽>-review`, 낱개 모드는 `review`가 규약이다. 세션 이름은 이 기계에서 하나만 쓸 수 있으므로 다른 저장소의 검토 세션이 이미 쓰고 있으면 `<저장소>-review`처럼 저장소 이름을 붙인다. 다르면 사용자에게 `/rename`을 권한다. 마스터는 이 이름으로 패킷을 보내고, `phase.sh init --review`에 이 이름이 들어간다.
4. **맥락을 남긴다** — `<게이트>/<폴더>/00-context.md`에 지금 상태(base tip · 열린 PR·이슈 · 워크트리 · 대기열 · 이 세션이 맡은 범위). 폴더는 에픽 모드 `<에픽>/`, 낱개 모드 `review-<YYYY-MM-DD>/`.
5. **첫 일거리를 제시한다** — 2절 또는 3절.

## 2. 에픽 모드

1. **하위 이슈가 있나 본다.** 에픽 본문의 체크 목록과 이슈 목록을 대조한다.
   - 없으면 **분해·발행이 첫 일거리다** — 초안 → 읽기 전용 서브에이전트(built-in `Plan` 등)에 응집·결합·역할 분담·PR 크기 관점 리뷰 1회 → 승인 절차 → 이슈 생성 → 에픽 본문 체크 목록 갱신 → 게시본을 받아 초안과 대조(`NN-publish-check.md`).
   - 본문에 **표에는 안 보이지만 배분해야 하는 것**(리뷰 후속·마이그레이션 제약·수용 기준 목록)이 숨어 있다. 어느 하위 이슈가 맡는지 빠짐없이 적는다.
   - 분해안 문서와 에픽 본문이 다르면 **본문이 이긴다**(본문이 나중에 갱신된다).
2. **마스터 착수 안내** — 동시에 셋까지가 적당하다. 워크트리는 브랜치를 만들고 상태에 쓰므로 이 세션이 실행하지 않는다. `<scripts>`를 실제 경로로 바꾼 명령을 사용자에게 주고, 사용자가 main 워크트리의 터미널에서 실행한다.
   ```sh
   sh <scripts>/wt.sh <이슈> <slug> [base]
   cd <워크트리> && claude -n <이슈>-<slug>
   ```
   새 세션 안: 계획 작성(설정 `planSkill` 또는 `${CLAUDE_PLUGIN_ROOT}/skills/tdd/plan-format.md`) → **「<이슈> 계획 검토」를 이 세션에 요청** → 반영 → `/multisession-tdd:tdd <이슈>`. **`phase.sh init --review <이 세션 이름>`**을 빠뜨리면 판정이 닿지 않는다.
3. **계획 검토 → 게이트 검토.** 게이트 패킷이 오면 `/multisession-tdd:gate-review <이슈> --latest`.
4. **선행 PR이 머지되면** — `grep -l '"base": "<그 브랜치>"' <루트>/state/*/session.json`으로 base가 그 브랜치인 마스터를 찾아, 살아 있는 세션(`ListAgents`)마다 「선행 <이슈> 머지됨(<base> <sha>) — base 전환(tdd 스킬 8절 4항)」을 보낸다.
5. **에픽이 끝나면** — 에픽 본문 체크 상자를 채우고, 무엇이 들어갔는지·무엇이 후속으로 열려 있는지 코멘트한 뒤 close한다(모두 승인 절차). 후속 이슈는 함께 닫지 않는다.

## 3. 낱개 모드

1. **첫 일거리는 「지금 봐야 할 것 추리기」다.** 열린 PR 중 리뷰가 없거나 재리뷰가 요청된 것을 골라 순서를 제안한다. 스택 PR이면 **아래부터**.
2. **PR 리뷰 사이클** — 미리뷰를 순서대로 본다. 도중에 올라온 반영본을 쫓아 재리뷰하지 않는다(다음 사이클).
   - 읽기 → 검사 → 지적 초안 → 승인 절차 → 게시 → 게시본 대조(`NN-publish-check.md`).
   - **검사 직전과 게시 직전에 PR head를 다시 잰다.** 작성자가 조용히 커밋을 얹으면 검사한 트리와 리뷰 대상이 어긋난다.
   - 가능하면 **head와 head+최신 base를 합친 트리** 둘 다 검사한다. 합친 트리는 임시 브랜치에서 만들고 검사 뒤 지운다(PR 브랜치에 합치지 않는다 — 실수로 push할 여지가 생긴다).
3. **자잘한 이슈 대응**도 같은 흐름이다 — 사실 확인 → 초안 → 승인 → 게시 → 대조.
4. 에픽 검토 세션이 따로 열려 있으면 **그 에픽에는 손대지 않는다.** 겹치면 메시지로 경계를 맞춘다.

## 4. 자원 교통정리 — 설정 `resources`가 있을 때

설정 `resources`(예: 「전체 빌드 검사」·「로컬 서버 포트」·「DB 컨테이너」)는 한 번에 한 세션만 쓰는 자원이다. 비어 있으면 이 절을 건너뛴다.

- 대기열은 **`<루트>/resource-queue.md` 하나**를 모든 세션이 같이 쓴다. 표(시각 · 세션 · 자원 · 상태)와 「위반 기록」 절을 둔다.
- **승인은 한 세션만 한다.** 검토 세션이 둘 이상이면 **가장 최근에 시작된 에픽 모드 검토 세션**이 조정 세션으로서 승인을 맡고, 나머지는 신청만 한다. 열릴 때 서로 메시지로 확인한다.
- **승인 전에 잰다** — 그 자원을 쓰는 프로세스·포트·컨테이너가 도는지, 메모리 여유와 부하(macOS `memory_pressure -Q`·`uptime`, Linux `free -m`·`uptime`). 모자라면 **조건부 승인**으로 시작 조건을 적어 보낸다.
- 무거운 전체 검사는 **포그라운드**로 돌리게 한다. 하네스가 메모리 부족으로 백그라운드 작업을 끊을 수 있다. 한 세션이 두 자원을 다 써야 하면 동시에 말고 차례로.
- **기대 건수를 미리 계산해 알린다** — 「base 기준 N건 + 이 PR이 더한 M건 = N+M. 그보다 적으면 이 PR 테스트가 안 돈 것이니 멈추고 알려라」. 이 한 줄이 검출력을 만든다.
- 반납 메시지에는 남은 프로세스·컨테이너·포트 수와 검사한 sha를 적게 한다.

## 5. 검토 요점

- **전제** — 워크트리 HEAD == 패킷 HEAD · 추적 파일 깨끗 · `git merge-tree --write-tree <base> HEAD` · phase·gateSeq.
- **게이트별 체크리스트**는 `gate-review/checklists.md`가 정본이다. 여기에 복제하지 않는다.
- **주장은 코드로 되짚는다.** 리뷰 의견이든 마스터 보고든 근거가 되는 자리를 직접 열어 본다. **결론이 맞아도 근거가 틀린 경우가 있고, 그 근거가 주석·문서로 굳으면 다음 사람이 그것을 믿는다.**
- **판단이 정적 판독에 그치면 그 한계를 적고**, 어느 해석에서도 참인 문구를 고른다.
- **머지 해결의 성격은 트리로 가린다** — `git merge-tree --write-tree <부모1> <부모2>`와 `git rev-parse <머지 커밋>^{tree}`가 같으면 손댄 자리가 없다(재검사 없이 승인을 새 head로 옮긴다). 다르면 차이를 보고, 내용이 바뀌었으면 전부 다시 돌린다.

## 6. 머지 지원 (사용자가 지시했을 때)

- 필수 CI를 돌릴 수 없는 상황이면 원인을 원문으로 확인한 뒤 **머지할 head + 지금 base를 합친 트리에서 로컬 검사 + PR에 사유 코멘트**로 대체한다. 브랜치에서만 돌린 결과는 base가 크게 움직인 뒤에는 근거가 약하다.
- 사유 코멘트는 머지 전에 올린다. 적을 것: 원인 원문 · **실제로 검사한 head와 base sha** · 건수 · 실행 시각. 검사 뒤 base가 움직였으면 sha를 바꾸지 말고 「검사 뒤 base가 <sha>로 갱신됐으나 차이는 … 뿐」 한 줄을 덧붙인다. 돌리지 않은 트리의 sha를 적으면 근거가 거짓이 된다.
- 머지 방식은 저장소 규약을 따른다. 로컬 브랜치가 워크트리에 잡혀 있으면 원격 브랜치 삭제 옵션이 실패할 수 있다 — 워크트리를 먼저 치우거나 원격 삭제는 저장소 설정에 맡긴다.
- gitignore된 계획 문서는 워크트리를 지우기 전에 사본을 뜬다.
- 머지 보고를 받으면 원격에서 대조해 `NN-merge-check.md`를 쓰고, **열린 브랜치들을 새 base로 `merge-tree` 재확인해 충돌을 각 세션에 알린다.**

## 7. PR 본문을 고칠 때

- **통째로 갈아끼우지 않는다.** `gh pr view <N> --json body --jq .body`로 받은 지금 본문을 바탕으로 바뀌는 절만 고친다.
- 그래도 교체해야 하면 승인 화면을 열기 전에 지금 본문과 새 본문을 `diff`하고, 첨부 자산 URL(이미지 등)이 하나라도 빠지는지 본다. 빠지면 멈추고 병합본을 만든다. 실행하는 세션도 명령 직전에 한 번 더 대조한다.

## 8. 기록과 인계

- 파일 이름: `NN-verdict.md` · `NN-review-notes.md` · `NN-publish-check.md` · `NN-merge-check.md` · `NN-pr-body*.md` · `NN-context.md`. 번호는 그 폴더 안에서 이어 붙인다.
- 메모리는 이슈별 상태와 규칙을 나눠 적는다.
- 사용자가 요구할 때만 핸드오프 문서를 만든다. 사본은 `<게이트>/`에 둔다.
- 세션을 닫을 때 대기열의 「현재」 줄을 비우고, 다음 조정 세션이 승인을 이어받는다는 한 줄을 남긴다.

## 하지 않는 것

- 마스터 대신 구현 판단 — 발견은 피드백으로만.
